# Eval results, v2 (2026-11-27): after fixing the two gaps v1 found

v1 ([v1.md](v1.md)) showed that information I had written down never reached the agents:

1. **No warehouse docs.** dbt only copies YAML descriptions into the database when `persist_docs` is
   on, and it was off, so `describe_table` returned `comment: null` for every table and column.
2. **Hidden table caveats.** `list_metrics` showed metric descriptions but not the descriptions of the
   semantic models behind them, which is where caveats like "2024-25 lists 20 managers as players"
   were written.

v2 fixes both (commit `96be669`): `persist_docs` is on for the marts (6 tables, 37 columns described),
and each metric in `list_metrics` carries `notes` from its semantic model. The warehouse data was
verified identical to v1, and the answer-format examples are now neutral (v1's leaked three answers).

## What was re-run

16 questions, chosen by rule rather than by hand: every question missed in v1 (q20, q21, q26, q36,
q40, q41, q49), questions whose traps the fixes target (q25, q31, q35, q39, q45, q46), and three
"canaries" that were 9/9 in v1, to catch regressions (q02, q11, q18). × 3 setups × 3 models, one run
each: 144 runs, **$3.71**. 11 Gemini runs first failed on infrastructure (the Gemini project hit its
monthly spend cap; 3 network drops) and were re-run after the cap was raised.

## What it shows

- **The table-notes fix did exactly what it was meant to.** The managers question (q40) went from 1/9
  to 7/9 correct, and every run with the semantic tools (B and C) got it right.
- **Every setup improved and the order held:** semantic + skill > semantic > SQL only. Setup C is 47/48.
- **No regressions:** the three canary questions stayed correct.
- **More context costs more.** Tool calls barely moved, but cost per run rose 12-18% because every
  request now carries more descriptive text.
