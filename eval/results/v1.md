# Eval results, v1 (2026-11-26)

450 runs: 50 questions × 3 setups × 3 models, 1 repeat each. Total cost **$8.59**. 0 API errors, 0 format errors.
Raw results and transcripts are in `eval/runs/full/` (git-ignored).

**Setups:** A = SQL tools only on the `marts` tables · B = A + semantic-layer tools · C = B + the
`warehouse-analysis` skill. **Models:** Claude Haiku 5.5, GPT-6.1 Terra, Gemini 3.8 Flash.

## Headline: accuracy on 47 clean questions

| Model | A: SQL only | B: + semantic | C: + semantic + skill |
|---|---|---|---|
| Claude Haiku 5.5 | 89.4% (42/47) | 93.6% (44/47) | **95.7%** (45/47) |
| GPT-6.1 Terra | 95.7% (45/47) | 95.7% (45/47) | **97.9%** (46/47) |
| Gemini 3.8 Flash | 97.9% (46/47) | 97.9% (46/47) | 97.9% (46/47) |
| **All models** | 94.3% (133/141) | 95.7% (135/141) | **97.2%** (137/141) |

Three questions are excluded: the answer-format instructions used example values that equalled the
gold answers of q01 (`344`), q17 (`"2024-25"`) and q43 (`{"home": 7.4, "away": 6.6}`). Every model
and setup saw the same examples, so the comparison between setups is unaffected, but those questions
can't count. The examples are now neutral, and a test fails if any example matches a gold answer.

## What it shows

1. **Clean modelling did most of the work.** Setup A, plain SQL on the dbt `marts` tables, already
   scored 94%. It solved every cross-season identity trap (Salah's 2,208 across a display-name change,
   "Groß" vs "Gross", players who changed clubs) from table and column names alone: the warehouse had
   **no** table or column descriptions (dbt's `persist_docs` was off).
2. **The semantic layer and skill help most where the model is weakest.** Haiku went 89% → 94% → 96%.
   The skill repeatedly fixed its "two different people with the same name" mistake (q20, q21).
   Gemini 3.8 Flash was at 98% in every setup.
3. **They cut tool calls by ~25%** (6.2 → 4.6), but not cost, as above.
4. **Some traps beat every setup.** The manager caveat (q40) lives in the semantic *model* description,
   which the tools never show the agent, so the semantic layer couldn't help. Terra's small-sample miss
   (q41) survived even the skill's explicit "use a minimum sample" rule.

## Caveats

- One repeat per question, and the differences between setups are a few questions each. Treat them
  as directional, not significant.
- Grading fixes made during the run, each applied by re-grading saved transcripts (no reruns): a
  labelled total alongside two people's separate values is accepted (q20/q21, 2 verdicts); a gameweek
  number inside a label is accepted (q28/q29, 3 verdicts). q49's packed label was left as wrong.
- No table/column docs in the warehouse (above); setup A worked from names only.

## Gaps found, for a v2

1. Turn on dbt `persist_docs`, so table and column descriptions reach the warehouse (and `describe_table`).
2. Show each metric's semantic-model notes in `list_metrics`, so caveats like the managers one reach the agent.
3. Neutral answer-format examples (done).
